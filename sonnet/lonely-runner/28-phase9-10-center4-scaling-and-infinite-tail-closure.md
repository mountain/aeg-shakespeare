# Phases 9–10 — center-4 scaling and infinite contact-tail closure

**Status:** center-3 -> center-4 frozen-rule replay passed; center-5 and the entire later contact tail are certified semantic no-ops for the resulting first-witness representation.  
**Branch:** `research/canonical-observer-api`  
**Scope:** four-runner first-witness contact semantics only; no new Lonely Runner theorem.  
**Holdout:** `K=13` remains frozen and was not used for representation development.

## 1. Why Phase 9 mattered

Phase 8 had closed the center-2 -> center-3 loop:

```text
local effect detection
-> canonical decomposition
-> minimum process-generated completion
-> task-relative objectification
-> controlled history interleaving/reconvergence.
```

The central scaling question was whether that procedure had merely been tuned to
one refinement step.

Phase 9 therefore froze the rules.  No center-2 -> center-3 wall identity,
completion count, or fresh-tree topology was allowed to become a proposal
heuristic for center 4.

The current center-3 state was represented as

```text
visible task/sign state
+ exact constraint provenance used only as a certificate/discovery backend.
```

This distinction became important twice: once when lazy semantic search queried
latent distinctions, and again when task minimization showed those distinctions
were not part of the minimal visible representation.

## 4. Phase 9B red team on latent constraint provenance

center 3 but whose signs were not explicit in the 28-predicate visible state.

representation.  Phase 9C explicitly minimized it and removed every latent old

\[
\boxed{

Exact closure provenance remains extremely useful for discovery and
certification, but Phase 9 does not force it into a public persistent-state API.

## 5. Phase 9C — one shared center-4 completion primitive

For each of the seven branching cells, Phase 9C took the complete collision-wall
union encountered by the lazy oracle, enumerated all exact feasible ternary sign
records, and searched every wall subset for the minimum task-separating support.

The result is unusually simple:

\[
\boxed{1,1,1,1,1,1,1}

All seven cells choose the **same** process-generated wall:

\[

```text

```

Six cells already have three complete raw sign classes.  One lazy candidate
grammar contains two walls and nine raw classes, but minimization again leaves
only the `19/11` ternary wall and three task classes.

### Independent sign-map certificate

The local full-stratum oracle gives, in every branching cell,

```text

                       0  -> exactly one task
                      +1  -> exactly one task.
```

Thus the one-wall completion is not an artifact of the lazy oracle.

No claim is made that every later layer or every process problem has a one-wall
completion.

## 9. Phase 10C — finite certificate for the infinite contact tail

Checking center 5 suggests a stronger observation.

For a fixed runner with positive speed `u_i`, event time is proportional to the
contact coefficient:

\[
t_{i,n,\mathrm{kind}}
=
\frac{\alpha_{n,\mathrm{kind}}}{u_i}.
\]

For every integer center `n >= 5`,

\[
\alpha_{n,\mathrm{kind}}
\ge
\alpha_{5,\mathrm{enter}}
=5-\delta
=\frac{24}{5}.
\]

Thus the center-5 enter event is the earliest event in the entire remaining
contact tail for each runner.

It is enough to compare those four anchor events against the current witness on
every closure atom:

\[
14967\times4=59868.
\]

The exact certificate is

```text
strict anchor comparisons        59868
earlier/equal                        0
unresolved                           0.
```

Therefore

\[
\boxed{
\text{every contact event at every center }n\ge5
\text{ lies strictly after the current first witness.}
}
\]

Consequently the finite 29-predicate center-4 presentation is sufficient for
the first-witness semantics of the **entire infinite remaining contact-event
alphabet** in this four-runner calibration.

This is the natural endpoint of contact-center refinement for Sonnet 001.
There is no mathematical reason to run center 6, 7, 8, ... individually.

## 11. API consequence

This sequence strengthens several distinctions but does **not** justify a large
new public object taxonomy.

### Stronger evidence

1. `CanonicalDecomposition` scales across a second contact refinement step.
2. Generated completion primitives can be much smaller than the solver trace
   used to discover/certify them.
3. History placement/reconvergence is a real representation problem independent
   of the primitive decision inventory.
4. A finite process presentation can become sufficient for an infinite future
   task alphabet.

### Still not promoted

- universal `Completion`;
- public `ConstraintCell`;
- public activation/reconvergence object;
- discrete `ObserverConnection`;
- universal future-sufficiency theorem;
- scalarized representation cost.

The closure atoms remain a research/certificate backend, not ontology.

## 12. Relation to the observer-ODE programme

This Sonnet sequence still does **not** instantiate the moving-observer ODE
idea.  The two nonbranching updates at centers 3 and 4 are history reindexing;
no intrinsic canonical observer frame moves.

Its contribution to the broader AEG Analysis programme is different: it shows
how a process representation can grow, quotient, interleave, and eventually
close an infinite history tail while preserving exact task semantics.

A genuine observation-path / `ObserverConnection` experiment should now be
sought in a problem where the local canonical frame actually changes, rather
than forcing that vocabulary onto Lonely Runner.

## 13. Claim boundary

No new Lonely Runner theorem is proved.

The exact result is internal to the declared four-runner relative-speed domain,
contact alphabet, and first-witness task.  The infinite-tail conclusion concerns
all later contact centers **for this task and this process model**; it is not a
statement that all Lonely Runner questions reduce to 29 predicates.

Likewise, the fact that center 4 required one common ternary wall and center 5
required none must not be extrapolated into a universal layer-growth law.

`K=13` remains a frozen holdout.
