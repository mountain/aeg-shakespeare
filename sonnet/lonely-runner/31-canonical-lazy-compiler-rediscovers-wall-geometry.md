## 3. Lazy symbolic provenance for the next contact only

The canonical runtime state does not need a contact center.  The symbolic compiler is allowed to keep a weaker object as **compiler provenance**: for each runner, only its next lifted contact boundary

\[
\alpha_i/u_i,
\]

with `alpha_i = n +/- delta` generated lazily from the previous event.

The update is local:

```text
exit at n + delta
    -> next enter at n + 1 - delta

enter at n - delta
    -> next exit at n + delta
```

No future center is generated until the process actually reaches it.

At one symbolic state, runners `i` and `j` can exchange next-event order only on

\[
\frac{\alpha_i}{u_i}
=
\frac{\alpha_j}{u_j},
\]

hence the compiler itself derives the equality coordinate

\[
\boxed{
\frac{u_j}{u_i}=rac{\alpha_j}{\alpha_i}.
}
\]

The ratio on the right is rational because the contact coefficients are generated from `delta` by the exact process law.

Thus ratio walls are no longer an externally chosen primitive alphabet.  They are equality loci generated by competition among canonical next events.

This is a symbolic unrolling of the canonical process, not an enumeration of an ambient contact-wall product.
