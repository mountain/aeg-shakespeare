# Phase 14 — task-relative completion on the same canonical process

**Status:** exact K=4/K=5 task-change calibrations passed.  
**Scope:** first-witness torus dynamics unchanged; observer/task enlarged by one natural future question.  
**Engineering boundary:** research-local only; no `src/` or public-API changes.  
**Open-frontier policy:** `K=13` remains frozen.

## 1. Why change the task instead of the process

Phases 11–13 established that, for the canonical first-witness task, contact-center growth is not intrinsic process-state growth and the tested four/five-speed domains remain clean-separable after task objectification.

That does **not** imply that the canonical first-witness terminal regions are sufficient for every natural observer on the same torus process.

Docs 38/39 require completion to be interpreted relative to both representation and task.  The cleanest independent pressure test is therefore to keep the canonical process fixed and strengthen only the task.

---

## 2. Safe-window task

For the usual first canonical witness retain

```text
(boundary runner/kind set, point-or-interval mode).
```

If the witness is a point, the richer task adds nothing.

If it opens a nonempty safe interval, additionally ask:

> which runner or simultaneous runner group first re-enters the bad set and therefore closes that safe interval?

Immediately after an interval witness every runner is safe, so the first interval-closing event is the next `enter` contact.  Its identity is a canonical next-event question generated by the same contact law.

No new physical dynamics or externally invented coordinate is introduced.

---

## 3. Exact task-sufficiency test

Replay the horizon-free compiler but retain, at each first-witness terminal region, the exact closure plus the next contact event of every runner.

For an interval terminal region `R`, compute every feasible exact next-minimum group under the old closure.

If all feasible branches have the same closer, `R` is sufficient for the richer task.

If one old terminal region admits two or more different closer groups, then

\[
\boxed{
R\text{ is first-witness sufficient but safe-window-task insufficient.}
}
\]

This is stronger than a decision-placement obstruction: the old canonical region itself contains multiple values of the richer task and must be continued/refined before any exact classifier exists.

The unchanged first-witness compiler reproduces


Under the safe-window task:

```text

```

Thus roughly

\[
\boxed{50/261\approx19.2\%}

of the previously sufficient canonical regions are not sufficient for the richer observer.

The next-event continuation encounters nine unresolved equality coordinates.  Only one of those nine is absent from the old first-witness process-generated coordinate union, but the union of all **minimum local completion supports** uses seven coordinates and introduces **no genuinely new coordinate** relative to that old global process grammar.

This distinction matters:

```text
old terminal region is task-insufficient
!=
old process-generated coordinate grammar is necessarily insufficient.
```

The representation needs refinement/continuation even when the required pairwise distinctions were already latent in the broader process grammar.


The 49 one-wall cases are clean-separable under their minimum support.

The exceptional three-wall case is not.

## 5. The exceptional K=4 parent is an exact three-event argmin obstruction

The exceptional first-witness task is

```text
witness boundary: runner 3 exit
mode:             interval.
```

After this witness, three runners remain as genuinely competing safe-window closers: `1,2,3`.  The old exact parent region admits all seven nonempty simultaneous-minimum sets:

\[
\boxed{
\{1\},\{2\},\{3\},
\{1,2\},\{1,3\},\{2,3\},
\{1,2,3\}.
}
\]

The minimum pairwise support is exactly the complete three-pair comparison grammar:

\[
\boxed{
\begin{aligned}
(u_2/u_1)&\ ?\ 9/4,\\
(u_3/u_1)&\ ?\ 7/2,\\
(u_3/u_2)&\ ?\ 14/9.
\end{aligned}}
\]

These are exactly the equality loci of the three candidate next-enter times.

Order the three pairwise event-time comparisons as `(1,2),(1,3),(2,3)`.  The exact partial-sign matrix is

```text
closer       signs
{1}          (-, -, ⊥)
{1,2}        (0, -, -)
{1,2,3}      (0, 0, 0)
{1,3}        (-, 0, +)
{2}          (+, ⊥, -)
{2,3}        (+, +, 0)
{3}          (⊥, +, +)
```

This is exactly the seven-stratum `argmin` geometry of three events:

- if one event is uniquely minimal, the relative order of the two losers is task-irrelevant and remains unresolved;
- if two tie for minimum, their comparison is equality and both precede the third;
- if all three tie, all comparisons are equality.

Therefore every pair of distinct closer tasks is separable, but **no pairwise coordinate is defined on all seven regions**.  The root family has no clean pairwise query.

Hence

\[
\boxed{
\text{pairwise task-separable}
\quad\text{but}\quad
\neg\operatorname{Clean}.
}
\]

Even the full local pairwise grammar remains obstructed.  This is the first real Sonnet contact-process instance of the Phase-13A abstract clean obstruction.

The important interpretation is not “add an Argmin API.”  It is only:

> pairwise wall materialization can be the wrong decision grammar for a naturally multiway next-event task, even when the pairwise grammar is information-theoretically sufficient.

A compound minimum-group description is a research candidate to compare against region refinement; it is not promoted here.

## 6. K=5 independent replay — completion occurs, but the local motif stays binary

Use the first five-speed transfer domain

\[
\delta=\frac16,
\qquad
\frac{u_5}{u_1}<\frac{21}{4}.
\]

The unchanged first-witness compiler gives

```text
3,397 symbolic states
1,117 first-witness terminal regions
33 canonical first-witness tasks
197 point parents
920 interval parents.
```

Under the safe-window task:

```text
129 / 1,117 old parents split
988 parents have one closer value
129 parents have three closer values
1,375 extended exact regions
67 extended tasks.
```

Thus the same task-relative completion phenomenon appears independently at the next runner dimension:

\[
\boxed{129/1117\approx11.5\%.}
\]

The next-event continuation encounters 31 unresolved equality coordinates, ten absent from the old first-witness generated union.

The exact minimum local support profile is much simpler than K=4:

```text
129 / 129 split parents require exactly one ternary comparison.
```

Their minimum supports are all clean.  Across those supports the union contains 13 coordinates, only one genuinely new relative to the old first-witness generated union.

The strongest representative parent has

```text
witness boundary: runner 4 exit
mode:             interval
closers:          {3}, {3,4}, {4}
minimum support:  u5/u4 ? 11/5.
```

Its partial-sign geometry is exactly the two-event argmin:

```text
{3}      (-)
{3,4}    (0)
{4}      (+)
```

which is clean by one ternary query.

So the K=4 obstruction is not merely “safe-window tasks are hard.”  The obstruction appears when the live closer race becomes genuinely three-way under a pairwise decision grammar.

## 7. What Phase 14 establishes

The same canonical physical/contact process can have

```text
first-witness task
    -> existing terminal carrier sufficient

safe-window-closer task
    -> some old terminal regions split
    -> task-relative completion reappears.
```

This occurs at both K=4 and K=5 without changing the process law.

Therefore the docs-38/39 warning is now supported inside Sonnet 001 itself:

\[
\boxed{
F_{\rm comp}\text{ is representation/task relative.}
}
\]

More specifically, Phase 14 separates three different phenomena:

1. **task-region insufficiency** — one old canonical region contains several richer-task values;
2. **pairwise completion content** — a small set of process-generated equality coordinates can separate those values;
3. **pairwise placement obstruction** — in the K=4 three-way argmin case, even the full pairwise grammar cannot classify the exact argmin regions cleanly without over-refining loser order.

Those must not be conflated into one generic `Completion` abstraction.

---

## 8. Engineering consequence

No new public object is justified.

In particular, Phase 14 does **not** promote:

```text
SafeWindow
FutureTask
ArgminPrimitive
Completion
CompletionObstruction
multiway contact API
```

The existing public API remains untouched.  The useful result is a research-local counterexample and an executable distinction between process sufficiency, task sufficiency, pairwise information sufficiency, and clean decision placement.

Before any abstraction is considered, an unrelated process domain would need to reproduce the same separation for independent reasons.

## 9. Next research gate

The next high-value comparison is local and concrete, not architectural.

On the exceptional K=4 three-way race, compare two exact representations of the **same** safe-window task:

```text
A. pairwise wall completion
   -> three pair comparisons
   -> pairwise-separable but clean-obstructed
   -> any ordinary pairwise decision tree must split loser order somewhere

B. one process-native minimum-group observation
   -> seven exact minimum-group values
   -> no loser-order refinement by construction.
```

Measure description cost, decision depth, region splitting, and reconstruction/certificate cost.

Only if a similar multiway primitive proves useful in another independent process problem should it create API pressure.

## Claim boundary

Phase 14 proves bounded exact task-relative representation results for the declared four- and five-speed domains.  It proves no new Lonely Runner case and no universal theorem that every three-way event race should be represented by a multiway primitive.
