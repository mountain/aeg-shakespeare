# Galilean II/III: from character obstruction to a central mass residual

**Status:** two executable calibrations; no new public API.

## 1. Why continue after the finite-family API freeze

The first finite-family API was deliberately frozen after Translation, Dilation,
A/M, and Galilean I.  Galilean I accepted the API on a genuinely mechanical
shear:

\[
(a,s)\mapsto(a+vs,s),
\]

with the corresponding bare character-label transport

\[
(p,E)\mapsto(p,E-vp).
\]

The obvious missing feature was the physical mass-dependent affine shift.  The
purpose of Galilean II/III is not to patch that feature in, but to ask whether
the missing information appears twice in independently checkable layers of the
same mechanical system.

## 2. Galilean II: an obstruction intrinsic to character pullback

For spacetime translations

\[
N_{(a,s)}N_{(b,r)}=N_{(a+b,s+r)},
\]

a scalar response is

\[
\chi_{p,E}(a,s)=e^{i(pa-Es)}.
\]

The frozen `transport_process_character` operation is pullback along a
`FamilyAction`.  Therefore the trivial character is fixed by construction:

\[
\chi\equiv1\quad\Longrightarrow\quad g^*\chi\equiv1.
\]

Equivalently, ordinary pullback cannot move the origin of character-label
space.  The Galilean shear gives only

\[
(p,E)\mapsto(p,E-vp),
\]

which is homogeneous in the old labels.

Hence any genuine transformation law that sends a rest label to a nonzero
momentum/energy pair requires information that is absent from bare scalar
character pullback.

This is an API-level obstruction, not yet a cocycle theorem.

## 3. Galilean III: the same missing information reappears in Hamiltonian form

Take canonical phase-space coordinates \((x,p)\), time \(t\), and mass \(m\),
with

\[
H=\frac{p^2}{2m},\qquad P=p,\qquad K=mx-tp.
\]

For the canonical Poisson bracket,

\[
\boxed{\{K,H\}=P},
\]

and more importantly,

\[
\boxed{\{K,P\}=m}.
\]

The residual \(m\) is central in the local mechanical sense relevant here: it
has zero Hamiltonian vector field in \((x,p)\).  Thus replacing Hamiltonian
generators by only their visible phase-space vector fields erases this residual.

This explains a striking finite fact.  Spatial translation and boost maps can
commute visibly on phase space, while their generator presentation still
retains the nonzero constant \(m\).

## 4. The affine energy-momentum shift

The finite boost flow generated by \(K\) is

\[
x\mapsto x-vt,
\qquad
p\mapsto p-mv.
\]

Consequently,

\[
H\mapsto
\frac{(p-mv)^2}{2m}
=
H-vp+\frac12mv^2.
\]

So the physical label transformation is affine:

\[
\boxed{
(p,H)
\mapsto
\left(p-mv,
H-vp+\frac12mv^2\right).
}
\]

At the rest label \((0,0)\) this becomes

\[
\left(-mv,\frac12mv^2\right),
\]

which Galilean II proved cannot arise from ordinary character pullback.

The dispersion relation is preserved:

## 5. What has now been learned about the API boundary

The two vignettes locate the same missing layer from opposite directions:

\[
\boxed{
\text{bare family action / scalar pullback}
\quad\text{forgets a central residual retained by generators.}
}
\]

This makes a cocycle/central-residual object a serious future candidate.
However, these are two layers of the **same** Galilean organism.  Following the
project's anti-over-abstraction rule, that is not yet enough to promote
`ProcessCocycle` to the public API.

The correct next test is an independent system in which visible process actions
again close only after discarding a central residual.  Magnetic translations
provide a natural candidate.

## 6. Five-line research ledger

**Primitive assumptions.** Frozen finite-family API for Galilean II; canonical
free-particle Hamiltonian realization for Galilean III.

**Forbidden structures.** No Galilei-group class, projective/unitary
representation API, group cohomology, public Poisson framework, or cocycle
object.

**Discovered structure.** Bare scalar pullback fixes the zero character; the
Hamiltonian generators retain the exact central residual `m`; the corresponding
finite boost produces the missing affine mass-dependent label shift.

**New reusable abstraction.** None.

**Unresolved manual choice.** Whether a common `ProcessCocycle` / central-residual
abstraction survives an independent calibration.

## 7. Claim boundary

This note does not claim that all central extensions, projective
representations, or symplectic moment-map phenomena should be represented by one
Shakespeare object.  It records one exact failure mode of the current API and
postpones abstraction until a second mathematical organism reproduces it.
